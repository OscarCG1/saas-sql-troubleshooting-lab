# INC-004 — Subscription Incorrectly Expired

## Incident Information

**Incident ID:** INC-004
**Priority:** P2 — Medium (simulated)
**Customer:** NextGen Analytics
**Category:** Subscription Management
**Status:** Investigation Completed — Resolution Pending

## 1. Problem Description

NextGen Analytics reported that its SaaS subscription was incorrectly displayed as expired.

According to the customer's subscription information, the contract remained valid until April 11, 2027.

The support investigation focused on identifying inconsistencies between subscription dates and the recorded subscription status.

## 2. Investigation

The investigation was performed using SQLite and DBeaver.

Two database tables were examined:

* `customers`
* `subscriptions`

### Step 1 — Subscription Verification

An SQL query was executed to retrieve the customer's subscription details.

**Findings:**

* Subscription ID: 4
* Subscription plan: Enterprise
* Recorded status: `expired`
* Start date: 2026-04-12
* End date: 2027-04-11

### Step 2 — Date Validation

The subscription's expiration date was compared against the current date using SQLite date functions.

**Finding:**

The subscription was marked as expired even though its contractual end date had not passed.

### Step 3 — Automated Inconsistency Detection

A SQL query was developed to identify subscriptions marked as expired while still within their validity period.

**Result:**

The query successfully identified NextGen Analytics as having an inconsistent subscription status.

### Step 4 — Conditional Status Evaluation

A SQL CASE WHEN expression was used to calculate an expected subscription status based on its start and end dates.

This provided an additional method for detecting inconsistencies between stored values and expected business conditions.

## 3. Findings

The investigation established that:

1. The subscription was recorded as `expired`.
2. The subscription end date was April 11, 2027.
3. The subscription was still within its contractual validity period.
4. The recorded status was inconsistent with the simplified date-based business rule used in the laboratory.

## 4. Root Cause Analysis

The inconsistency was intentionally introduced into the simulated database to reproduce the reported incident.

In a production environment, similar inconsistencies could result from:

* Incorrect automated status updates.
* Subscription synchronization failures.
* Application processing errors.
* Incorrect subscription-management configuration.

The original cause of a comparable production incident would require further investigation.

## 5. Recommended Actions

1. Verify the subscription contract and renewal information.
2. Review application logs and subscription status update processes.
3. Confirm the expected status using the application's business rules.
4. Obtain authorization before making corrections.
5. Apply the approved correction through the supported application workflow.
6. Validate the subscription status after the correction.
7. Confirm that the customer can access the subscribed services.

**Investigation:** Completed

**Resolution:** Pending

No corrective database update was performed during the investigation.
